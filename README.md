# 网易云音乐缓存还原工具

这是一个 Windows / Python 脚本，用来扫描网易云音乐 Android 客户端导出的 `Music3` 缓存目录，将可识别的 `.nmsf` 音频缓存还原为常见音频文件，并按歌曲名命名。

脚本按样本观察到的字节异或 `0xA3` 处理缓存，再根据还原后的文件头识别 M4A、MP3、FLAC、WAV 或 Ogg。`.nmsf` 的内部格式没有官方规范；不同客户端版本、缓存类型或后续更新可能改变这些规律。请先用 `--dry-run` 检查输入，再处理自己的缓存副本。

## 功能

- 递归扫描 `Music3` 下的子目录，并按缓存索引中的歌曲 ID 查询歌名和歌手。
- 输出音频文件名使用“歌名 - 歌手”；同一首歌有多个缓存版本时，会附加版本码以避免重名。
- 为每首保留同名 `.config`。有原配置时逐字复制；缺少配置但音频可还原时，根据音频格式生成最小配置。
- 根据 `.nmsfi` 的文件大小和已缓存分块估算完整度。缺索引的 M4A 缓存会尝试从 MP4 box 长度推算。
- 完整度低于 50% 的条目从**输出目录**中移除音频和配置，并记录歌曲名；原始 `.nmsf` 备份不会被删除。
- 完整度为 50%–99% 的条目会保留并标记为部分缓存，播放时仍可能在中途结束。
- 生成 `restore_report.csv`，记录每条缓存的来源、歌曲 ID、完整度、结果和输出路径。
- 若歌曲 ID 在目录接口中无记录或接口不可用，使用 `歌曲ID <id> - 元数据未找到` 命名并在报告中注明，不依赖 LLM。

## 要求

- Python 3.10 或更高版本
- 网络连接：用于按歌曲 ID 查询标题和歌手。查询失败时脚本会使用 ID 回退名继续处理。
- 输入缓存目录应包含类似下面的文件结构：

```text
Music3/
  1/
    <file_id>_0.nmsf
    <file_id>.nmsfi
    <file_id>.config
  2/
    ...
```

`.config` 或 `.nmsfi` 缺失时，脚本会按可用信息处理；无法估算完整度的条目会跳过并写入报告。

## 使用

默认输入是当前工作目录下的 `网易云音乐备份\Music3`，默认输出是 `D:\网易云音乐备份`。如果目录在其他位置，请显式传入路径：

```powershell
python .\restore_netease_cache.py `
  --source "D:\path\to\Music3" `
  --output "D:\网易云音乐备份"
```

建议先预检：

```powershell
python .\restore_netease_cache.py --source "D:\path\to\Music3" --dry-run
```

常用选项：

```powershell
# 只处理按路径排序后的前 30 个缓存
python .\restore_netease_cache.py --source "D:\path\to\Music3" --limit 30

# 遇到同名结果时停止，不覆盖
python .\restore_netease_cache.py --source "D:\path\to\Music3" --no-overwrite

# 清除输出目录里旧流程留下的 ID 形式 .nmsfi/.config 侧车文件
python .\restore_netease_cache.py --cleanup-only --output "D:\网易云音乐备份"
```

默认会覆盖已存在的同名输出，方便重复运行和续跑。`--no-overwrite` 可以关闭此行为。脚本只读取输入缓存；低缓存清理和旧侧车文件清理仅作用于输出目录。

## 输出示例

```text
D:\网易云音乐备份\茉莉花 - 蒋大为.m4a
D:\网易云音乐备份\茉莉花 - 蒋大为.config
D:\网易云音乐备份\restore_report.csv
```

## 限制

- 字节异或处理和 `.nmsfi` 完整度估算是基于实际缓存样本归纳的，不保证覆盖所有网易云客户端版本。
- 标题查询依赖歌曲 ID 的目录记录。若歌曲下架、不可访问或接口没有返回标题，脚本会以 ID 命名，不会猜测歌曲名。
- “达到 50%”不代表音频完整。报告会列出所有部分缓存；低于 50% 的缓存不会输出还原音频。
- 输出的 `.config` 用于保留播放器相关参数，不包含歌曲名等完整媒体标签。
